# 检索、图像与引用操作细则

## 检索矩阵

围绕当天一个研究问题，每类最多优先挑选能回答问题的几份材料：

| 问题 | 首选渠道 | 记录内容 |
|---|---|---|
| 人口、GDP、产业、财政、收入 | 统计局公报、七普、年鉴 | 年份、地域、单位、常住/户籍、现价/可比价 |
| 行政、面积、地理 | 政府概况、自然资源、民政 | 边界版本、县域/城区/建成区区别 |
| 历史和人 | 地方志、档案、文保、博物馆、学术论文 | 原文、卷次/页码、时代和地名对应关系 |
| 规划布局 | 自然资源部门公示、批准文本、政府公开附件 | 规划期、公示/批复状态、图号/页码、审图信息 |
| 民间说法 | 旧报、论坛、旅行记录、口述 | 最早可见出处、独立支持、反证、待核方法 |
| 实驾事项 | 交通、气象、景区、边境管理当日公告 | 发布时刻、适用路段、人群与有效期 |

搜索结果只用来**找到**原文，不拿搜索摘要作论文级引文。网页有标题与发布日期但图片没有拍摄日期时，分别记录，不能推成同一天。官网沉默不是传闻的反证；大量转载也不是独立证据。

## 图件处理

1. 先找网上已有的城区、区域或地形图；记录来源页、机构、版本和许可。
2. 另找官方国土空间或城市规划的**布局图**。先判定批准、草案或维护版本，读清图题与图例。若正文采用草案图，文字结论用较新批准文本交叉复核，明确两者差异。
3. PDF 可渲染为PNG以便核对页码和视觉质量。示例命令：`pdftoppm -f 23 -l 23 -scale-to 1800 -singlefile -png input.pdf planning_page`。保留PDF原链接和图在PDF中的页码。若原件无再发布许可，公开GitHub只放链接，不上传渲染图。
4. 自制路线图可用 SVG，图内直接写“示意图、非测绘底图”；不能画成精确测绘成果。
5. 照片至少两张、逐张打开检查。若仅是区域参照，不标成目的地现场；不能把旧照当今天的天气、施工或营业证明。保存原图URL、来源页、作者、发布日期、已知拍摄日与许可。

## 路由处理

明确起点和终点是旅馆、城市中心、景区入口还是研究参考点。记录查询工具、查询日、距离和模型驾驶时间。中间镇若只在路线附近而未确认经过镇区，写“方向”或“沿线参照”；不能把模型小时数当冬季安全行车预算。山区、林区、边境和长距离路段另列燃油、住宿、手机信号、道路封闭与替代锚点。

## 引用与表达

正文最邻近关键事实处用 `[1]` 等编号；文末参考文献写机构/作者、题名、日期、原始链接、访问日期。PDF写页码；古籍写书名卷次，无法核对的引语标转引/待核。一个推断可同时引用几条事实，但仍标明“基于证据的推断”。第一人称只在明确的模拟驾驶、观察段落出现。
