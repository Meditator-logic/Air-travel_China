# 每日执行工作流

## 1. 模型与工具条件

Agent 需能读取和写入 `PROJECT_ROOT`、访问互联网、保存文本与图像、计算北京时间。推荐具备搜索、官方网页访问、PDF 阅读或渲染、图片查看、地图和路由查询能力。没有特定工具时可替换实现，但**不得伪称已检索或已核验**。

## 2. 唯一事实来源

`旅行状态.json` 是当前进度的机器可读依据；根 `目录.md` 和最近主日志供人类复核。旧技术说明中的“当前状态”可能过期，不可优先于状态文件。路线总纲给出整趟走廊，`next_five_anchors` 给出接下来五个**住宿**锚点。

## 3. 执行顺序

1. **门禁**：读状态、目录、路线总纲、最近主日志和本仓库两份规范。`journey_status != active` 返回 D。核对状态字段、最后日志存在、日期和归档；今天已完成返回 C。运行 `preflight.py` 可辅助检查。
2. **路线**：只执行未来五站的第一项。先检查它是否向下一宏观检查点推进、可作为住宿聚落、与最近十日及 `closed_counties` 不冲突、不会造成同一聚落第三夜。若改线，先重算五站并记录原计划、原因及闭环影响。
3. **研究问题**：一天只选一个问题，例如“河流与铁路如何组织城区”。历史、统计、规划、产业、饮食和景点围绕它取舍，不堆砌百科清单。
4. **联网检索**：优先统计公报、普查、地方志、自然资源与规划、文保与博物馆、档案、学术论文，再用可靠媒体补充。保留网页 URL、机构、发布日期、访问日期和关键原句或页码。民间传说只作线索，记录支持、反证和待核方法。
5. **路线与视觉**：查询参考路由，标注距离、模型耗时、主要道路、中间聚落；冬季、山地、边境道路留现实预算。寻找网上城区/区域图、官方规划布局图、至少两张地点明确的实景照片；制作一张标“示意图、非测绘底图”的路线图。核对图片实际显示内容。图件注明来源、版本、规划状态和时效。
6. **写作**：按模板写题注、结论、路线、数据底账、证据链、分时段模拟行程、事实/推断/模拟/待核、夜宿与未来五站。正文用 `[1]` 编号，文末列完整参考文献。第一人称只用于标明的模拟驾驶与观察。
7. **先归档、后推进**：将主日志、来源 JSON、媒体、核验记录写到 `省份/城市或住宿聚落/`；更新地方目录和总目录。检查本地链接、媒体文件、引用、唯一夜宿、数据口径和闭环。**全部成功后**更新 `旅行状态.json` 的日期、序号、夜宿锚点、未来五站、停留计数和下一检查点。
8. **返回结果**：A 完整归档并给主日志可点击绝对路径；B 阻断并说明文件/来源/路线缺口，不推进状态；C 当日已完成；D 非 active 并说明状态。不可只交研究摘要。

## 4. “走一步想五步”

今天完成后，原第2—5项变成未来四站，再补一个沿宏观走廊的第五站。例如：海拉尔驻留 → 额尔古纳 → 根河 → 满归 → 满归驻留。第5、10、15等旅行日做路线审计：重复县域、住宿夜数、剩余天数、闭环可行性、道路和补给风险。

普通县级区域最多连续3个旅行日；内容特别丰富最多4日；累计5篇主日志后必须离开；同一住宿聚落最多连续2夜。离开县域后十个旅行日内不自动折返。题材丰富不能成为延长理由。

## 5. 具体数据判读

- 2020七普常住人口与2025户籍人口不可直接相减。
- 县域GDP、财政收入、机场吞吐量不可当作城区或单一景区的数据。
- 规划期目标不是今日现状；公示草案图不是批准版。正文若合读两版，应指出差异。
- OSRM等路由模型只有几何距离与理想驾驶时间，冬季路况、施工、入口和服务区须另查。
- 官方网页上的图片也可能是旧照片；页面发布日期、素材上传时间、拍摄日期分别标明，未知就写未知。

## 6. 故障处理

网络不通：可用已保存的官方来源，但标明资料获取日期和未能更新的范围；若关键事实或路线无法核实，返回 B。图片不足：说明检索渠道和缺项，不能用其他城市照片冒充。部分文件写入失败：不推进状态，修复归档后同日重试。用户要求修订：创建版本后缀，维持原旅行序号和夜宿锚点。
