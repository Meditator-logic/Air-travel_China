# 每日一城路线控制规范 v1

## 1. 目的

本规范解决每日调研被局部资料牵引、在同一县域反复派生专题、偏离闭合环线的问题。路线控制优先于资料丰富度；地方专题可以进入“未来专题清单”，不能自动延长当前旅程。

## 2. 每趟旅程启动条件

启动前必须在旅行状态中写明：

- 旅程编号、名称、状态；
- 起点锚点和必须抵达的终点锚点；
- 宏观走廊及其顺序；
- 预计总天数和允许浮动天数；
- 当前阶段、下一阶段检查点；
- 未来五个住宿锚点；
- 不走或暂缓进入的区域；
- 季节、道路、边境、住宿等主要风险。

没有终点和宏观走廊，不得把旅程状态设为 active。

## 3. “走一步想五步”

每天选定下一站前，必须同时规划未来五个住宿锚点。次日只执行列表中的第一项。若道路、天气、住宿、边境管理、资料可靠性或用户指令导致改线，应重新计算五站，并记录：原计划、改线原因、对闭环天数的影响。

未来五站至少满足：

1. 连续可达，方向一致；
2. 每一步有可住宿的人类聚落；
3. 总体上接近下一宏观检查点；
4. 不违反停留上限和折返冷却期；
5. 留有一个可替代锚点，但替代点不能反向拉回已完成县域。

## 4. 防止打转的硬约束

- 普通县级区域连续最多3个旅行日；历史、规划或民族文化特别丰富者最多4日。
- 同一县级区域累计达到5篇主日志后必须离开，除非用户明确要求继续驻留。
- 同一住宿聚落最多连续2夜；第三夜必须有用户明确指令或不可抗原因。
- 离开县级区域后10个旅行日内不得折返；宏观闭环必经或用户指定除外。
- 已在日志中写明“收束”“离开”“完成本段”后，状态文件必须把该县列入 closed_counties；自动程序不得自行重开。
- 当日下一站必须缩短到下一宏观检查点的路线距离，或在状态中记录可核验的地理、安全、补给理由。
- 资料丰富、图片充足、存在新传闻、还有乡镇未写，均不能单独构成延长或折返理由。

## 5. 路线偏移预算

每一阶段允许为专题绕行，但建议绕行总里程不超过该阶段主通道估算里程的20%，额外停留不超过2天。超出后必须：

- 放弃或推迟专题；
- 重新估算剩余天数；
- 判断是否仍能抵达闭环终点；
- 在路线审计中说明。

## 6. 定期路线审计

每5个旅行日或每完成一个宏观阶段时执行一次审计：

- 是否持续接近下一宏观检查点；
- 最近10天是否重复县域或住宿聚落；
- 县域累计日志数是否超限；
- 未来五站是否完整且连续；
- 按当前速度能否在预计窗口内回到终点；
- 是否有专题应转入未来专题清单；
- 是否需要压缩驻留、跳过次要节点或调整走廊。

审计结果写入旅行状态和当日归档核验记录。

## 7. 结束规则

- 正常结束：抵达 required_end_anchor，状态设为 completed。
- 提前结束：用户要求终止但尚未闭环，状态设为 terminated，准确记录实际终点，不虚构返程。
- 暂停：仅用于等待季节、道路或用户安排，状态设为 paused，保留未来五站。
- completed 或 terminated 状态下，自动任务不得生成新日志。

## 8. 状态字段最低要求

旅行状态至少包含：journey_status、journey_id、start_anchor、required_end_anchor、macro_corridor、current_stage、next_macro_checkpoint、next_five_anchors、closed_counties、recent_counties、days_in_current_county、days_at_current_settlement、route_deviation_reason、estimated_total_days、estimated_remaining_days、last_route_audit、next_route_audit_day。
